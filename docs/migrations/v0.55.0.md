# Migrating to v0.55.0

`smtp.ProdSender.SendMail` times each SMTP command as RFC 5321 asks, instead of one budget for the
whole exchange. Its errors also say whether another attempt can deliver the mail.

## Do I need to act?

**Yes, if a send must end within a fixed time.** `SendMail` no longer reads `Timeout`. Each step now
takes RFC 5321's timeout, up to 10 minutes, and a slow relay can hold a send far longer than
`Timeout` did. `Ping` keeps `Timeout`, so a readiness check still answers within it.

**Yes, to retry a failed send.** Each error now carries the class that decides it.

## Time each command

`ProdSender.Timeouts` bounds each step. A zero field takes its value from `smtp.DefaultSendTimeouts`:

| Field             | Bounds                                   | Default |
| ----------------- | ---------------------------------------- | ------- |
| `Greeting`        | DNS, the connection and the 220 greeting | 5 min   |
| `Command`         | EHLO, STARTTLS, AUTH and QUIT, each      | 5 min   |
| `Mail`            | MAIL                                     | 5 min   |
| `Rcpt`            | RCPT, for each recipient                 | 5 min   |
| `DataInit`        | DATA                                     | 2 min   |
| `DataBlock`       | Each 4 KiB block of the message          | 3 min   |
| `DataTermination` | The reply to the final `.`               | 10 min  |

A server that stops answering ends the send within the current step's timeout. A server that answers
every step just before its timeout holds the send for the sum of the steps.

A job whose platform kills it at a deadline sizes that deadline for its sends. A request that waits
for its mail moves the send out of the request, or shortens the fields.

Drop any setting that only fed `Timeout` for sends, such as an `SMTP_TIMEOUT` variable, once the
release that ignores it runs.

## Retry by failure class

Every error `SendMail` returns matches exactly one class through `errors.Is`:

| Class               | Cause                                                                       | Next step                      |
| ------------------- | --------------------------------------------------------------------------- | ------------------------------ |
| `smtp.ErrTransient` | A 4yz reply, or a network failure before the final `.`                      | Retry later                    |
| `smtp.ErrPermanent` | A 5yz reply, a missing STARTTLS or AUTH, or a template that does not render | Give up                        |
| `smtp.ErrUncertain` | No reply after the final `.`                                                | Give up: the relay may hold it |

```go
err := sender.SendMail(to, tmpl, lang, data)
if errors.Is(err, smtp.ErrTransient) {
	// Retry after a delay. RFC 5321 asks for at least 30 minutes.
}
```

## Notes

A failed QUIT no longer fails a send. The reply to the final `.` already accepted the mail, so a
retry would deliver it twice.
