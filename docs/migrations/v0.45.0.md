# Migrating to v0.45.0

A server drains as it should on shutdown: requests and unary calls in flight finish, and long-lived
gRPC streams end the moment shutdown begins, instead of holding the drain to its deadline.

## Do I need to act?

**Yes, if you call `grpcf.NewServer`.** It takes the process context first, and stops compiling until
you pass it.

## Pass the process context to `grpcf.NewServer`

```go
// before
server := grpcf.NewServer(cfg.Otel, cfg.Logger, cfg.App.DowntimeStart, ctxInterceptor)

// after
server := grpcf.NewServer(ctx, cfg.Otel, cfg.Logger, cfg.App.DowntimeStart, ctxInterceptor)

err := grpcf.ListenAndServe(ctx, cfg.Grpc, server)
```

Pass the context the server is served under. When it is done, the server's streams end with
`UNAVAILABLE`, so their clients resume on another instance, and the drain no longer waits for them
until `GRPC_TIMEOUT_SHUTDOWN` forces a stop. Unary calls still finish within the drain.

## REST requests drain

Nothing to change. `httpf.NewServer`, which `httpf.ListenAndServe` calls, gave every request a context
canceled the moment shutdown began, so requests in flight were cut instead of drained. Request
contexts now keep the context's values only: a request in flight finishes within
`REST_TIMEOUT_SHUTDOWN`, and the server closes whatever still runs at that deadline. A handler that
stopped early on its context's cancellation at shutdown now runs until it finishes or the deadline
closes it.
