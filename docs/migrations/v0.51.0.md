# Migrating to v0.51.0

golib reports server faults to Sentry through the new `sentryf` package, and removes the unused
`otelpresets.Sentry`, which sent client IPs.

## Do I need to act?

**No, in every service.** No service imports `otelpresets.Sentry`, and the reporter sends nothing
until a service installs it with a DSN. Code that still uses `otelpresets.Sentry` stops compiling.

Adopting the reporter is recommended: the sections below cover it.

## Replace `otelpresets.Sentry`

`otelpresets.Sentry` exported traces to Sentry. Traces now stay on the other `otelpresets`
backends, and Sentry receives error events only:

```go
// before
Otel: &otelpresets.Sentry{DSN: dsn, Release: release, Environment: environment},

// after
Otel:   &otelpresets.Gcloud{ProjectID: projectID, FlushTimeout: otelFlushTimeout},
Sentry: sentryf.LoadConfig(getEnv),
```

## Install the reporter

Read the standard `SENTRY_DSN`, `SENTRY_RELEASE` and `SENTRY_ENVIRONMENT` variables, install the
reporter at boot, and flush it before the process exits:

```go
cfg.Sentry = sentryf.LoadConfig(getEnv)

lo.Must0(sentryf.Init(cfg.Sentry))
defer sentryf.Flush(2 * time.Second)
```

`SENTRY_RELEASE` names the deployed build as `<service>@<semver>`, such as
`service-authentication@2.17.0`. With a DSN, `Init` fails without a release and an environment.
Without a DSN, it installs nothing: local runs and tests report nothing and open no connection.

The servers then capture each fault where it surfaces, with no change to the handlers:

| Capture point                               | Fault                                          |
| ------------------------------------------- | ---------------------------------------------- |
| `httpf.HandleError`                         | a 5xx status, grouped by method and route      |
| `httpf.NewRouter`                           | a handler panic                                |
| `grpcf.NewServer`                           | a call ending with `Internal` or `Unavailable` |
| `loggingpresets.GRPCLocal` and `GRPCGcloud` | a handler panic                                |
| `otel.RecoverPanic`                         | a panic on a detached goroutine                |

A 4xx, a planned downtime refusal and any other gRPC status send nothing.

## Keep the cause of a gRPC fault

Sentry groups the faults of a method by the type of the innermost error. A bare status error wraps
nothing, so every fault of a method lands in one issue. Answer a fault with `grpcf.Fault`, which
sends the caller the same status and keeps the cause for Sentry:

```go
// before
_ = otel.ReportError(span, err)

return nil, status.Error(codes.Internal, "internal error")

// after
return nil, grpcf.Fault(codes.Internal, "internal error", otel.ReportError(span, err))
```

## Report a job's failure

A job's `main` reports its failure under the job's name, before the deferred flush runs:

```go
if err != nil {
	err = otel.ReportError(span, fmt.Errorf("rotate keys: %w", err))
	sentryf.Capture(ctx, "rotate-keys", err)

	return err
}
```

## Notes

Tests that assert on captured events install a recording reporter with
`sentryftest.Record(t)`. The reporter is process-wide, so such a test cannot run in parallel.
