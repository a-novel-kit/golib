# Migrating to v0.61.0

golib removes the `sentryf` package, `sentryf/sentryftest` with it, and
`grpcf.GcloudCredentialsProvider`, which dialed a Google Cloud endpoint with a Google-issued
identity token (a-novel-kit/golib#721). `github.com/getsentry/sentry-go` and
`google.golang.org/api` leave golib's dependencies with them.

golib's servers, panic recovery and `worker.Poll` no longer send faults to Sentry. Each fault stays
on its span and in its log, which Grafana alerts on. `httpf.Serve` and `grpcf.ListenAndServe` return
their error to the caller alone.

## Do I need to act?

**No, in every service.** No service imports `sentryf` or names `GcloudCredentialsProvider`. Check a
repository from its root:

```bash
grep -rnE 'golib/sentryf|GcloudCredentialsProvider' --include='*.go' .
```

No output means nothing to do. Code that still uses either stops compiling.

Run `go mod tidy` after the bump. It drops the modules golib no longer requires, such as
`github.com/getsentry/sentry-go`, unless the service imports them.

## Remove the Sentry reporter

Delete the `sentryf.Init` and `sentryf.Flush` calls, any `sentryf.Capture` in a job's `main`, and
the `SENTRY_*` settings the service reads, such as `SENTRY_DSN`. A test drops its
`sentryftest.Record` call and the assertions on the events it recorded.

## Replace `GcloudCredentialsProvider`

Dial a service in the same Kubernetes cluster with its service token, read from the file the
kubelet projects it into:

```go
// before
&grpcf.GcloudCredentialsProvider{Host: host}

// after
&grpcf.ServiceTokenCredentialsProvider{ServiceTokenPath: serviceTokenPath}
```

Dial a plaintext local target with `&grpcf.LocalCredentialsProvider{}`.
