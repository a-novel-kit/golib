# Migrating to v0.36.0

PostgreSQL test-support helpers now live only in `postgres/postgrestest`. This keeps `postgres` production-only: importing it no longer brings test harness dependencies into service builds.

## Do I need to act?

**Required if you use a PostgreSQL test helper.** The deprecated exports from `postgres` have been removed. Production database access, transactions, and migrations stay in `postgres`.

## Import the dedicated test-support package

Move test harness calls and test-only types to `postgrestest`.

```go
// before
import "github.com/a-novel-kit/golib/postgres"

postgres.RunDBTest(t, config, migrations, func(ctx context.Context, t *testing.T) {})

// after
import "github.com/a-novel-kit/golib/postgres/postgrestest"

postgrestest.RunDBTest(t, config, migrations, func(ctx context.Context, t *testing.T) {})
```

The moved names are `TransactionalTestFunc`, `RoundtripOptions`, `ErrUnsupportedSchemaObject`, `NewContextTest`, `RunIsolatedTransactionalTest`, `RunTransactionalTest`, `RunDBTest`, `RunMigrationRoundtripTest`, `SchemaSnapshot`, and `SnapshotDelta`.

Keep importing `postgres` alongside `postgrestest` when a test also calls production helpers such as `GetContext` or `NewContext`.

## Notes

All first-party services migrated before this release. The removal is a package-boundary cleanup; it does not change disposable-database, roundtrip, census, cleanup, or parallel-test behavior.
