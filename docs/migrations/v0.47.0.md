# Migrating to v0.47.0

golib drops the exports no service uses, writes its initialisms in one case, and stops asking
`httpf.SendJSONStatus` for a context it never read.

## Do I need to act?

**Yes, in every service.** Each one sets `ProjectId` on its Google Cloud loggers, and each calls
`httpf.SendJSONStatus`. Both stop compiling. The edits are mechanical and fit in the pull request that
bumps golib.

| Service                  | Edits                                                                                    |
| ------------------------ | ---------------------------------------------------------------------------------------- |
| service-authentication   | `SendJSONStatus` in 13 handlers, `ProjectId` once, `ForceUnencryptedTls` once            |
| service-genai            | `SendJSONStatus` in 2 handlers, `ProjectId` twice                                        |
| service-json-keys        | `SendJSONStatus` in 3 handlers, `ProjectId` twice                                        |
| service-narrative-engine | `SendJSONStatus` in 1 handler, `ProjectId` once, `HttpHandler` once, 29 deprecated calls |
| service-template         | `SendJSONStatus` in 6 handlers, `ProjectId` twice                                        |

## Drop the context of `httpf.SendJSONStatus`

```go
// before
httpf.SendJSONStatus(ctx, w, span, http.StatusOK, loadItem(item))

// after
httpf.SendJSONStatus(w, span, http.StatusOK, loadItem(item))
```

Rewrite every call from the service root:

```bash
gofmt -r 'httpf.SendJSONStatus(a, b, c, d, e) -> httpf.SendJSONStatus(b, c, d, e)' -w internal
```

A handler that declared `ctx` for that call alone then fails with `declared and not used`. Remove
the declaration.

## Rename the miscased fields and methods

Go writes an initialism in a single case. The JSON and YAML keys keep their names, so configuration
files need no change.

| Before                                                                      | After                 |
| --------------------------------------------------------------------------- | --------------------- |
| `loggingpresets.LogGcloud.ProjectId`, `loggingpresets.GRPCGcloud.ProjectId` | `ProjectID`           |
| `smtp.ProdSender.ForceUnencryptedTls`                                       | `ForceUnencryptedTLS` |
| `otel.Config.HttpHandler`                                                   | `HTTPHandler`         |
| `otel.Config.RpcInterceptor`                                                | `RPCInterceptor`      |
| `postgres.ErrNoDbInContext`                                                 | `ErrNoDBInContext`    |

Each service sets `ProjectId` in `internal/config/app.config.default.go`:

```go
// before
var LoggerProd = &loggingpresets.LogGcloud{
	ProjectId: env.GcloudProjectId,
}

// after
var LoggerProd = &loggingpresets.LogGcloud{
	ProjectID: env.GcloudProjectId,
}
```

`env.GcloudProjectId` belongs to the service and compiles unchanged.

service-authentication sets `ForceUnencryptedTls` in the same file. service-narrative-engine calls
`cfg.Otel.HttpHandler()` in `cmd/rest/main.go`.

## Return values instead of calling `otel.ReportSuccess`

`otel.ReportSuccess` and `otel.ReportSuccessNoContent` are deprecated, and a later release removes
them. They record nothing, so return the value directly and drop the call:

```go
// before
return otel.ReportSuccess(span, &project), nil

otel.ReportSuccessNoContent(span)

// after
return &project, nil
```

Both still compile, but staticcheck reports each call as `SA1019`, so a service whose `lint-go` runs
staticcheck fails until the calls go. Only service-narrative-engine still makes them. Rewrite the
calls from the service root, then delete each `otel.ReportSuccessNoContent(span)` line:

```bash
gofmt -r 'otel.ReportSuccess(a, b) -> b' -w internal
```

A call that names its type argument, such as `otel.ReportSuccess[T](span, value)`, needs the same edit
by hand.

## Removed exports

No service uses these, so no service changes.

| Removed                                                             | Use instead                                                                                     |
| ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `otel.AppName`                                                      | `otel.SetAppName` to set the name. `otel.Tracer` and `otel.Logger` apply it.                    |
| `grpcf.SetEchoServersContext`                                       | `grpcf.RegisterEchoServers(server).SetServingStatus("", healthpb.HealthCheckResponse_SERVING)`. |
| `grpcf.Serve`                                                       | `grpcf.ListenAndServe`.                                                                         |
| `grpcf.BaseContextUnaryInterceptor`, `BaseContextStreamInterceptor` | The `baseContext` argument of `grpcf.NewServer`.                                                |
| `postgres.PassthroughTx`, `postgres.NewPassthroughTx`               | `postgrestest.RunTransactionalTest`.                                                            |
| `postgres.NameLen`                                                  | Nothing.                                                                                        |
| `postgrespresets.CreateSchema`                                      | `DBSchema` with `create` set.                                                                   |
| `config.JSONMapParser`, `config.JSONSliceParser`                    | `config.LoadEnv` with a parser of your own that calls `json.Unmarshal`.                         |
| `loggingpresets.LipColorError`, `LipColorWarn`, `LipColorInfo`      | Nothing. The Local presets keep their colors.                                                   |
