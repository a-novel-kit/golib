# Migrating to v0.38.0

Telemetry now follows OpenTelemetry's error-recording guidance, so a trace records each fact once.
Handlers can also tag error responses with details the client may see, and validation errors are
tagged by default.

## Do I need to act?

**Recommended.** Nothing stops compiling, but span statuses, error response bodies and Cloud log
fields change. Check the comparisons and dashboards below, and remove the calls that became no-ops.

## Compare reported errors with errors.Is

`otel.ReportError` now marks the error it returns, so the spans it propagates through skip a
description the first span already holds. The returned error wraps the original: an `==` comparison
against it no longer matches.

```go
// before
if err == ErrNotFound {

// after
if errors.Is(err, ErrNotFound) {
```

`errorlint` flags the old form.

## Remove success reporting

A successful operation leaves its span status unset. `otel.ReportSuccess` and
`otel.ReportSuccessNoContent` now record nothing; return the value directly.

```go
// before
return otel.ReportSuccess(span, user), nil

// after
return user, nil
```

## Report on handler spans only for server faults

`httpf.HandleError` marks the handler span failed for a 5xx and leaves a 4xx unset, as
OpenTelemetry's HTTP server convention does; `httpf.SendJSONStatus` no longer sets a status for the
HTTP status it sends. A gRPC handler follows the same rule by hand: call `otel.ReportError` before a
server-fault code (`Internal`, `Unavailable`) and return a client-error code (`InvalidArgument`,
`NotFound`) without it. Spans no longer carry exception events.

Alerting on span status counts only server faults after this release. Alert on the server span's
HTTP or gRPC status code for client errors.

## Tag error responses for the client

`httpf.WithTag` attaches a public tag to an error before the handler passes it to `HandleError`,
which then answers with an RFC 9457 problem details body (`application/problem+json`) carrying the
tags. A nil value sends `true`.

```go
if errors.Is(err, core.ErrAccountExists) {
	err = httpf.WithTag(err, "accountExists", nil)
}

httpf.HandleError(ctx, logger, w, span, errMap, err)
```

A client error whose chain holds a `go-playground/validator` error is tagged automatically with
`invalidFields`, mapping each field's lower camel path to the rule it broke:

```json
{
  "type": "about:blank",
  "title": "Unprocessable Entity",
  "status": 422,
  "tags": { "invalidFields": { "email": "email", "roles[0]": "role" } }
}
```

A service that joins validator errors with its own `ErrInvalidRequest` gets this without code
changes. Document the body on the validation responses of your `openapi.yaml`. Untagged errors
still answer with plain status text.

## Update Cloud Logging queries

- `LogGcloud` entries carry `message` and `severity` instead of `msg` and `level`, and an entry
  logged under a span links to its trace. The gRPC Cloud preset now sets `severity` as well.
- `HTTPGcloud` no longer opens its own `[METHOD] host./path` span. The OpenTelemetry server span is
  named after the matched route instead (`GET /v2/jwks`), and the access log's `requestUrl` omits
  the query string.
- `LogGcloud.Out` sets the writer; set it before the first entry.

## Notes

- golib now requires `uptrace/bun` v1.3.0, whose `Count` returns an `int64`. Tests that compare a
  count to an untyped `1` need `int64(1)` or a typed scan.
- golib now requires `go-playground/validator/v10`.
- The gRPC panic recovery returns a fixed `internal error` message; the panic value goes to the span
  and the log only.
