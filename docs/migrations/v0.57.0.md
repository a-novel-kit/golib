# Migrating to v0.57.0

golib spreads in-cluster gRPC calls across pods, retries a refused call on another one, and serves a
server's calls in flight to an autoscaler (a-novel/.github#536).

- A `ServiceTokenCredentialsProvider` connection balances its calls `round_robin` and retries every
  method that answers `Unavailable`, up to 4 attempts, under a retry throttle. Cloud Run and local
  connections keep `pick_first` and no retry.
- `NewServer` closes each connection after 30 seconds, gracefully, so clients resolve their target
  again and reach new pods.
- `NewCallLimit` replaces `MaxConcurrentCalls`, which stays as a deprecated wrapper. A `CallLimit` is
  both the server option and an `http.Handler` serving the gauge `grpc_server_calls_in_flight`.

## Do I need to act?

**Callers: no.** In-cluster callers balance and retry without a code change, once their service
runs this golib.

**Servers: keep one rule.** The retry rests on it: `Unavailable` means the call did not run. A
`CallLimit` and a planned downtime refuse that way, before the handler. A handler that has had an
effect, such as a write or a paid call, answers another code.

**GenAI: recommended.** Switch the call cap to `NewCallLimit` and serve its gauge on a port of its own,
so the cluster can scale on calls in flight (a-novel/service-genai#478):

```go
// before
grpcf.MaxConcurrentCalls(cfg.MaxConcurrentCalls)

// after
callLimit := grpcf.NewCallLimit(cfg.MaxConcurrentCalls)
// Pass callLimit to grpcf.NewServer as an extra option, and serve it on the metrics port:
// http.ListenAndServe(":"+metricsPort, callLimit)
```

`MaxConcurrentCalls` keeps working until a later release removes it.
